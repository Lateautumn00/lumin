# 批量重命名（file-renamer）字段级功能清单

> 版本：v0.1.0 · 定稿日期：2026-11-18（R8）· 工具 id：`file-renamer`
> 本文件为该里程碑验收附件；实现与本文件不一致时以本文件为准，变更须走 R8 流程。

## 1. 范围与边界

**做**：单个目录内普通文件的批量改名（规则叠加 → 实时预览 → 冲突校验 → 串行执行 → 会话内撤销）。

**不做**：目录递归、文件夹改名、跨目录移动、按 EXIF/内容改名、跨会话撤销、正则高级语法（仅 `$1`–`$9` 反向引用）。

## 2. 页面字段清单

| 区域   | 控件                                    | 行为                                                        | 空/默认           |
| ------ | --------------------------------------- | ----------------------------------------------------------- | ----------------- |
| 目录行 | 输入框 + [选择]                         | [选择] 走壳 `pickDirectory`；选中即 `set-dir` 记忆并扫描    | 回填 `lastDir`    |
| 目录行 | [重新扫描]                              | 重新 `scan` 当前目录                                        | 目录为空时禁用    |
| 规则区 | 六个规则卡片                            | 见 §3；任一输入非法 → 预览不生成并标红                      | 全部默认关闭/空   |
| 规则区 | [重置规则]                              | 恢复 §3 默认值                                              | —                 |
| 列表区 | 全选 / 反选                             | 勾选参与本次重命名的文件                                    | 默认全选          |
| 列表区 | 行：勾选框/原名/新名/大小/修改时间/状态 | 新名冲突 → 红字 + 原因；未勾选行灰显（仍显示预览）          | —                 |
| 操作区 | [执行重命名]                            | 仅当存在 `ok` 项且无 `conflict` 项时可点；提交 `apply` 任务 | 禁用              |
| 操作区 | [取消]                                  | 执行中显示；`lumin:task:cancel`                             | 仅 running 可见   |
| 操作区 | [撤销上一次]                            | 会话内最近一次成功 apply 的反向 pairs；成功后清空           | 无历史时禁用/隐藏 |
| 操作区 | 进度条                                  | `current/total` + 当前文件名                                | —                 |
| 结果区 | 摘要                                    | 「成功 N 个，失败 M 个」+ 失败明细（原名/错误码/文案）      | 无结果时隐藏      |

## 3. 规则定义（**作用顺序**：删除字符 → 查找替换 → 大小写 → 序号 → 日期 → 扩展名；规则卡片按此顺序排列）

仅作用于主名，扩展名独立处理。

| 规则     | 字段                                                                                               | 约束/语义                                                                     | 默认 |
| -------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ---- |
| 删除字符 | `enabled`、`from`(1–255)、`count`(0–255)                                                           | 从主名第 `from` 个字符起删除 `count` 个（超出长度则删到末尾，按码点计）       | 关闭 |
| 查找替换 | `enabled`、`find`、`replace`、`isRegex`、`caseSensitive`                                           | `enabled` 且 `find` 非空才生效；正则非法 → 标红不生成计划；`$1`–`$9` 反向引用 | 关闭 |
| 大小写   | `mode`(none/lower/upper/capitalize)                                                                | `capitalize`：每个以空白/`-_` 分隔的词首字母大写，其余小写                    | none |
| 序号     | `enabled`、`position`(prefix/suffix)、`start`(1–99999)、`digits`(1–8)、`separator`(空/`-`/`_`/`.`) | 序号基于「勾选且参与本次」的列表顺序（扫描结果按名称排序），从 `start` 起补零 | 关闭 |
| 日期     | `enabled`、`position`、`format`(`YYYYMMDD`/`YYYY-MM-DD`/`YYMMDD-HHmmss`)、`source`(mtime/now)      | `now` 为统一时间点（执行/预览时取一次）；`mtime` 逐文件取修改时间             | 关闭 |
| 扩展名   | `mode`(keep/lower/custom)、`custom`(1–10 位字母数字，不含点)                                       | `custom` 真正替换扩展名（如 jpg→jpeg）；原文件无扩展名时 `custom` 会追加      | keep |

**名称拆分语义**：`name.lastIndexOf('.') > 0` → 主名 + `.ext`；否则整串为主名、扩展名为空（`.gitignore` 不视为扩展名）。

## 4. 名称校验（命中任一 → 该行 `conflict`，禁止执行）

| #   | 规则                                                                        | 错误码                       |
| --- | --------------------------------------------------------------------------- | ---------------------------- |
| 1   | 主名为空或只含空白                                                          | `FR_NAME_INVALID`            |
| 2   | 含 Windows 保留字符 `< > : " / \| ? *` 或 ASCII 控制字符（0x00–0x1F）       | `FR_NAME_INVALID`            |
| 3   | 保留设备名（不区分大小写，含带扩展名形式）：`CON PRN AUX NUL COM1–9 LPT1–9` | `FR_NAME_RESERVED`           |
| 4   | 全名以空格或点结尾                                                          | `FR_NAME_INVALID`            |
| 5   | 全名 UTF-8 字节数 > 255（中文按 3 字节）                                    | `FR_NAME_INVALID`            |
| 6   | 与同批次其它目标重名（lowercase 比较，重复组全部标冲突）                    | `FR_CONFLICT`                |
| 7   | 与目录内「未勾选」的现存项重名（lowercase 比较）                            | `FR_CONFLICT`                |
| 8   | 新名与原名 lowercase 相同                                                   | 非冲突，`skip`「名称未变化」 |

> 链式/交换（目标恰为另一待改文件的原名）按第 6/7 条归 `FR_CONFLICT`，一期不做临时中转。

## 5. IPC 通道

| 通道                   | 类型 | 入参                                              | 出参                                                                                                        |
| ---------------------- | ---- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `file-renamer:scan`    | sync | `{dir}`                                           | `{files:[{name,size,mtimeMs}],truncated}`；仅普通文件、不递归；>5000 条截断                                 |
| `file-renamer:apply`   | task | `{dir,pairs:[{from,to}]}`（1–5000）               | `{taskId}`；progress `{current,total,message}`；done `{renamed:[{from,to}],failures:[{from,code,message}]}` |
| `file-renamer:undo`    | task | `{dir,pairs:[{from,to}]}`（from=当前名，to=原名） | 同上                                                                                                        |
| `file-renamer:config`  | sync | `{}`                                              | `{lastDir: string \| null}`                                                                                 |
| `file-renamer:set-dir` | sync | `{dir}`                                           | void（settings `lastDir`）                                                                                  |

**批量语义**：执行前对整批复核目标占用（已存在且不属于本批来源 → 该条 `FR_CONFLICT` 不执行，其余继续）；单条失败不中断；取消 → 跳出并保留已完成项，队列终态 `CANCELLED`。

## 6. 错误码

| 码                 | 中文文案                                               | 可重试 |
| ------------------ | ------------------------------------------------------ | ------ |
| `FR_DIR_NOT_FOUND` | 目录不存在或无权访问                                   | 是     |
| `FR_NO_FILES`      | 目录内没有可重命名的文件                               | 否     |
| `FR_NAME_INVALID`  | 文件名不合法（含保留字符、空白或超长）                 | 否     |
| `FR_NAME_RESERVED` | 使用了 Windows 保留名（CON/PRN/AUX/NUL/COM1–9/LPT1–9） | 否     |
| `FR_CONFLICT`      | 目标名已存在或与其它文件重复                           | 否     |
| `FR_RENAME_FAILED` | 重命名失败，文件可能被占用或无权限                     | 是     |
| `FR_TOO_MANY`      | 目录文件过多（上限 5000）                              | 否     |
| `FR_CANCELLED`     | 已取消（已完成的重命名保留）                           | 否     |

## 7. 三态要求（AGENTS §5.3）

| 状态   | 表现                                                                                          |
| ------ | --------------------------------------------------------------------------------------------- |
| 空态   | 未选目录：说明文案 + [选择目录] 主按钮；目录无文件：「该目录没有文件」                        |
| 加载态 | 扫描中 NSpin 骨架；执行中进度条 + 当前文件名 + [取消]                                         |
| 报错态 | 错误码 → 中文文案 + [重试]（仅 `FR_DIR_NOT_FOUND`/`FR_RENAME_FAILED`）+ [详情]（detail 折叠） |

## 8. 撤销

- apply 成功后 renderer 保存 `lastUndo = renamed.reverse().map(({from,to})=>({from:to,to:from}))`
- [撤销上一次] 提交 `undo` 任务；成功项从 `lastUndo` 移除，全部成功后清空并重新扫描
- 撤销前同样做目标占用复核；被占用条目记 `FR_CONFLICT` 并保留在 `lastUndo`

## 9. 验收断言

1. 前缀序号：3 文件 → `001-a.png` 式命名，磁盘实际名与预览一致
2. 查找替换（文本/正则 `$1`）+ 大小写 + 扩展名 custom 叠加结果正确
3. 八类名称校验逐条命中并给出对应错误码
4. 批内重名 / 与未勾选现存项重名 → 全部标 `FR_CONFLICT`，执行按钮禁用
5. 执行中取消 → 终态 `CANCELLED`，已完成项保留、无临时文件残留
6. 撤销恢复原名
7. R2 八类异常逐条实测记录于 `docs/smoke/file-renamer.md`
