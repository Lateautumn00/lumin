# fs-cleaner（文件清理）冒烟记录

> 工具：`fs-cleaner`（M41，2026-11-21）
> 规格：`docs/spec/fs-cleaner.md` · 任务单：`docs/spec/fs-cleaner-tasks.md` · 自动化：`apps/desktop/e2e/fs-cleaner-smoke.spec.ts`
> 手工复现环境：Windows x64 · Electron 45.3.1 · 本地离线
> 结论：八类异常全部有覆盖路径；删除只走系统回收站（可还原），e2e 不真实删除以免污染本机回收站。

## 2. R2 八类异常逐条

| 类别             | 场景与验证                                                                                                                           | 结果 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ---- |
| 1. 中文/空格路径 | 用例 2/3：`子目录 甲`、`根 文件.txt`、`empty/one/two`（临时目录名保持 ASCII，规避本机 Node fs 非 ASCII 目录崩溃）                     | 通过 |
| 2. 文件被占用     | 单测 `node.test.ts` touch 应用：`utimes` 抛 `EBUSY` → 计入 `failures`（`FC_TOUCH_FAILED`）且其余文件继续；扫描侧 stat 失败计入 `skipped` | 通过 |
| 3. 加密文件       | 不适用（仅读目录结构/时间属性，无解密语义）；不可读目录跳过不中断                                                                     | 不适用 |
| 4. 超大文件       | 目录树/空目录/临时文件均只依赖目录项与 stat，不读文件内容，超大文件无额外开销（文件数上限 20 万）                                     | 通过 |
| 5. 任务取消       | 单测 `node.test.ts`：已 abort 的 signal → 立即收敛（`scannedDirs=0`）；renderer「已取消」提示由 `use-task.test.ts` 覆盖               | 通过 |
| 6. 并发溢出       | 任务队列并发上限由壳统一控制（超限排队）；每页签同一时刻只允许一个任务（running 时按钮禁用）                                          | 通过 |
| 7. 磁盘满         | 扫描为只读；唯一写盘是回收站（系统托管），失败逐条返回 `failed` 且不中断剩余批次；`utimes` 失败计入 `failures`                        | 通过 |
| 8. 断电恢复       | 无中间产物（扫描只读、改时间原子于单文件），强杀重启后重新扫描即可；不涉及临时文件残留                                                 | 通过 |

## 3. 不可实测项说明

- **真实移入回收站**：e2e 不真实删除（避免污染 CI/本机回收站）。手工验证建议：对临时目录制造空文件夹/`.log` 文件，勾选 → [移入回收站] → 在系统回收站确认可还原。
- **20 万条上限**（`FC_TOO_MANY_FILES`）：e2e 造数成本过高，由单测注入 `MAX_SCAN_FILES + 1` 条目录项覆盖同一代码路径。
- **创建时间**：Node 无原生 API，工具明确只改 mtime/atime（页内常驻说明，spec §4 同口径）。

## 5. 设置记忆

- 键：`tools.fs-cleaner.lastRoot` / `.treeDepth` / `.treeExclude` / `.tempExtensions`；非法存量回落默认值（单测覆盖）。
- 四页签共享 `lastRoot`；`treeDepth/treeExclude/tempExtensions` 由 ToolView 防抖 400ms 统一保存，避免相互覆盖。
