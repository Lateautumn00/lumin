# duplicate-finder（重复文件查找）冒烟记录

> 工具：`duplicate-finder`（M18，2026-11-19）
> 规格：`docs/spec/duplicate-finder.md` · 自动化：`apps/desktop/e2e/duplicate-finder-smoke.spec.ts`
> 手工复现环境：Windows x64 · Electron 45.3.1 · 本地离线
> 结论：八类异常全部有覆盖路径；真实删除走系统回收站（可还原），e2e 仅验证失败项以免污染回收站。

## 1. 自动化结果（e2e 8 用例）

| #   | 用例                               | 断言                                                                                                                                     | 结果 |
| --- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 1   | 页面加载 + 空态引导                | 清空记忆目录后：标题可见、引导文案「先选择要扫描的目录…」、[开始扫描] 禁用                                                                | 通过 |
| 2   | 递归扫描（中文/空格路径 + 子目录） | `文件 一.txt`/`文件 二.txt`/`子目录 甲/文件 三.txt` 合成 1 组；size 6、`hash=SHA256("abcdef")`、wasted 12；`scannedFiles=4`；有进度事件  | 通过 |
| 3   | 非递归 + 阈值                      | `recursive=false` → 仅根目录 2 文件成组、`scannedFiles=2`；`minBytes=100` → 无组、`scannedFiles=3`                                        | 通过 |
| 4   | UI 全链路                          | 预置目录 → 扫描出「第 1 组 · 6 B × 2」→ 默认勾选 1（保留最早）→ 全选 2 → 全不选 0（按钮禁用）→ 恢复 1；首行未勾选、次行勾选               | 通过 |
| 5   | 根目录非法 + 回收站失败项          | 缺失目录任务终态 `DF_ROOT_INVALID`；`trashPaths([缺失路径])` 返回 `trashed=[]`、`failed` 含路径与系统原因                                | 通过 |
| 6   | 任务取消                           | 2×128MB 同内容文件，提交后立即 cancel → 终态 `done` 或 `CANCELLED`（无残留任务）                                                          | 通过 |
| 7   | 3 任务并发                         | 三个目录各 2 文件同内容，3 个 scan 并发全部 `done`，`totalWastedBytes` 均为 9                                                             | 通过 |
| 8   | 断电恢复                           | 扫描 128MB 文件时 `taskkill /T` 强杀 → 重启后再扫描同目录成功，1 组 2 文件、可释放 128MB                                                   | 通过 |

## 2. R2 八类异常逐条

| 类别             | 场景与验证                                                                                                             | 结果 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------- | ---- |
| 1. 中文/空格路径 | 用例 2：目录内 `文件 一.txt`、`子目录 甲/文件 三.txt`（临时目录名保持 ASCII 规避本机 Node fs 非 ASCII 目录崩溃）         | 通过 |
| 2. 文件被占用     | 单测 `collectFiles`：stat/读取失败计入 `skipped` 不中断（EACCES/EBUSY 同分支）；批量读取失败仅少一个候选，不影响其他组 | 通过 |
| 3. 加密文件       | 不适用（纯读取字节，无解密语义）；不可读文件归入 `skipped`                                                              | 不适用 |
| 4. 超大文件       | 用例 6/8：128MB 文件参与前缀（64KB）→ 全量哈希；按字节推进度、可取消                                                     | 通过 |
| 5. 任务取消       | 用例 6：cancel → 队列 terminate worker → `CANCELLED`（或瞬间完成 `done`）                                                | 通过 |
| 6. 并发溢出       | 用例 7：3 任务并发；队列并发上限由壳控制（超限排队）                                                                     | 通过 |
| 7. 磁盘满         | 扫描为只读；仅「移入回收站」写系统回收站，失败逐条返回 `failed`（用例 5 验证失败路径），不中断其余                      | 通过 |
| 8. 断电恢复       | 用例 8：任务中强杀主进程，重启后重扫成功；无中间产物（只读扫描，无输出文件）                                              | 通过 |

## 3. 不可实测项说明

- **真实移入回收站**：e2e 不真实删除（避免污染 CI/本机回收站），仅验证失败项与桥接返回值；手工验证建议：对临时目录重复文件勾选后点「移入回收站（n）」，在回收站可还原。
- **20 万文件上限**（`DF_TOO_MANY_FILES`）：e2e 造数成本过高，由单测 `collectFiles(maxFiles=1)` 覆盖同一代码路径。
- **磁盘满**：回收站由系统管理，无法定向模拟 ENOSPC；失败项路径已由用例 5 覆盖。

## 5. 设置记忆

- 键：`tools.duplicate-finder.lastRoot` / `.recursive` / `.minBytes`；非法存量回落 `null / true / 1MB`（单测覆盖）。
- e2e 用例 1 显式 `root: ''` 清空记忆，保证空态断言不依赖用例顺序。
