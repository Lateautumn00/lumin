# ocr-text（图片文字识别）冒烟记录

> 工具：`ocr-text`（M20，2026-11-19）
> 规格：`docs/spec/ocr-text.md` · 自动化：`apps/desktop/e2e/ocr-text-smoke.spec.ts`
> 手工复现环境：Windows x64 · Electron 45.3.1 · 本地离线 · `binaries/ocr` 模型齐全（det/rec/字典）
> 结论：八类异常全部有覆盖路径；真实推理由 e2e 直连 PP-OCR 验证，导出走 IPC 契约（原生目录选择框不可自动化）。

| #   | 用例                                                   | 断言                                                                                                                                                                | 结果 |
| --- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 1   | 页面加载 + 空态 + 损坏图/空白图/超大图错误态           | 侧边栏「图片文字识别」→ 标题可见、引导文案「拖拽图片到此处，或点击选择」、格式提示；损坏图 →「图片无法读取，请换一张清晰的图片」；空白图 →「未识别到文字，请换更清晰的图片」；21MB →「图片超过 20MB，请压缩后重试」；每次错误后「重新选择图片」可复位 | 通过 |

## 2. R2 八类异常逐条

| 类别             | 场景与验证                                                                                                                                                        | 结果 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 1. 中文/空格路径 | 用例 2：输入 `sample 1.png`、输出目录 `中文 目录`、产物 `sample 1-OCR.txt` 全链路可读写                                                                           | 通过 |
| 2. 文件被占用     | 单测 `node.test.ts`：`checkExclusive`/`checkReadable` 抛 `EBUSY`/`EPERM` → `OCR_FILE_LOCKED`（`detail` 保留 errno）；e2e 未构造真实占用（只读打开图片通常不阻塞）  | 通过 |
| 3. 加密文件       | 不适用（图片无解密语义）；加密容器伪装 `.png` 与用例 1 损坏图同分支 → `OCR_INPUT_INVALID`（「图片无法读取…」）                                                    | 不适用 |
| 4. 超大文件       | 用例 1：21MB PNG → `OCR_IMAGE_TOO_LARGE`（「图片超过 20MB…」），预检即拒绝、不启动 worker                                                                          | 通过 |
| 5. 任务取消       | 单测 `node.test.ts`：取消信号原样传给 `runTask`（壳终止 worker → `CANCELLED`）；UI 识别中显示「取消」；单图识别 <2s，e2e 未断言取消时点                             | 通过 |
| 6. 并发溢出       | 用例 3：5 个导出并发文件名互不冲突；识别任务由壳队列并发上限控制，超限排队                                                                                        | 通过 |
| 7. 磁盘满         | 导出走 `writeAtomic`（临时文件 + rename）；写失败 → `OUTPUT_WRITE_FAILED`（单测覆盖映射与失败透传），不残留半成品；未做 ENOSPC 定向实测（说明见 §3）               | 通过 |
| 8. 断电恢复       | `writeAtomic` 保证目标文件要么旧内容要么完整新内容；识别无中间产物；e2e 未强杀（说明见 §3）                                                                      | 通过 |

## 3. 不可实测项说明

- **真实文件占用**：Windows 下图片查看器以共享读打开，难以稳定制造 EBUSY；占用映射由单测覆盖同一代码路径。
- **磁盘满**：未建 VHD 定向模拟 ENOSPC；`save-txt` 写失败分支由单测（`writeFileSync` 抛 `EPERM`）覆盖。
- **断电恢复**：原子写语义由 `node-kit.writeAtomic` 单测与实现保证；e2e 强杀会破坏 Playwright 会话，未纳入。
- **取消时点**：单图识别秒级完成，e2e 点击「取消」存在竞态；取消链路复用壳通用 `lumin:task:cancel`（已在 shell 冒烟覆盖）。
