# Vibe Coding Skills - Git Master

- 分支规范严格锁死：main/prod 只读、dev 受控、feature/_ 开发、fix/_ 修复、hotfix/\* 线上紧急修复
- 提交信息强制规范：feat/fix/docs/style/refactor/test/chore 前缀，语义清晰，禁止模糊文案
- 严禁直接推送到主分支：所有代码必须走 PR/MR 流程，禁止直推 main/prod
- 提交粒度必须合理：小步提交、功能独立、不混编多需求、不携带无关变更
- 严禁提交敏感信息：密钥、Token、密码、证书、环境配置一律过滤
- 严禁垃圾提交：debug 日志、console、临时注释、无效代码禁止提交
- 冲突处理规范：必须手动解决冲突，禁止粗暴覆盖、保留他人代码逻辑
- 提交前自检：编译通过、格式化完成、Lint 无报错、无冗余文件
- PR 规范：描述清晰、关联需求、标注风险、必须通过门禁校验
- 代码合并纪律：未评审、未测试、未通过门禁一律禁止合并
- 提交历史整洁：禁止大量冗余提交，必要时 squash 合并提交
- 版本发布规范：打 Tag 遵循语义化版本，记录变更日志
