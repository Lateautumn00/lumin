**核实到的具体缺口**（规划依据，非猜测）：

- `task-queue.ts` 是**单一全局队列**（`concurrency` + `maxPending=100`、内存态），soffice 串行靠 `docx2pdf` 工具内 mutex 实现；无按工具配额、无任务历史、无重启恢复，R2.8 断电恢复目前靠各工具 smoke 手工验证。
- i18n 只在壳层：`renderer/src/i18n/zh-CN.ts` 21 个 key；工具内中文硬编码（exam-split 68 处、docx2pdf 43 处、单位换算 12 处、计算器 9 处），Q9 的「预留结构」尚未收口。
- `electron-builder.yml` 的 `publish.url` 仍是占位地址，M5 前必须替换（单点配置）。
- `README.md` 仍是 Gitee 初始化模板，M5 需重写。
- `LuminBridge` 目前只有 `invoke / onTaskEvent / onUpdateEvent / getAppInfo / openLogDir / getPathForFile / revealPath / settings`，无系统级集成能力。

## 1. 规划原则

1. **先收口再扩张**：M3b → M4 → M5 兑现既定路线，首发可安装包优先于新工具。
2. **复用优先**：候选工具按「能复用多少现有资产」排序，不引平行方案（AGENTS §1）。
3. **零耦合不可破**：跨工具复用一律上提根 `packages/`，禁止工具互 import；编排只走文件中立格式。
4. **每项标变更成本**：是否触发 R8 决策变更、是否改 `AGENTS.md` 依赖白名单 / 性能口径。
5. **不放松门禁**：新工具照旧三态 + 8 类 smoke + chunk gzip + 覆盖率 + `pnpm gate` 全绿。

## 5. 推荐节奏

| 版本                | 主题         | 交付                                                                                                | 门槛                                 |
| ------------------- | ------------ | --------------------------------------------------------------------------------------------------- | ------------------------------------ |
| v0.3b → v0.4 → v1.0 | 兑现既定路线 | M3b OCR、M4 下载、M5 首发                                                                           | 各里程碑原验收 + 门禁全绿            |
| v1.1                | 平台收口     | 全局任务中心 / 按工具配额、i18n 收口、深色主题 + 1 个低成本新工具（`text-toolbox` 或 `file-batch`） | 不新增第三方依赖，验证 R8 流程可复用 |
| v1.2                | 能力复用     | `pdf-kit` 上提 + `pdf-toolkit`；M4 已落地则加 `media-convert`                                       | chunk gzip 预算、R2 八类、覆盖率     |
| v1.3+               | 按需解锁     | 热插拔 / 本地推理增强 / 系统级集成 / 签名 / macOS                                                   | 逐项单独评审，不做打包承诺           |

**节奏原则**：每版仍产出可安装包，随时可停；平台能力优先于新工具数量——壳能力每提升一层，后续工具的边际成本就降一层。

## 6. 生效流程（任何条目开工前，R8 检查清单）

1. 改 `plan.md` §1 决策总表（新增/修订 Q 或里程碑行）+ §6 里程碑表。
2. 同步 `AGENTS.md`（工具范围 / 依赖白名单 / 性能口径 / 依赖方向）。
3. 出 `docs/spec/<tool>.md` 字段级功能清单（按钮集 / 输入项 / 错误分支），作为验收附件。
4. 三态（空 / 加载可取消 / 结构化错误码中文文案）+ tokens + `@lucide/vue`。
5. IPC：工具自带 zod schema + 类型化 client + 结构化错误码；长任务走三段式。
6. `docs/smoke/<tool>.md`：R2 八类异常逐条真实记录；运行时资产 raw/gzip 单列。
7. chunk 增量 ≤200KB gzip（求值类 ≤300KB）；核心纯函数 ≥80%、全仓 ≥60%。
8. `pnpm gate` 全绿 → `CHANGELOG.md` → MR（main 只读）。

### 7.1 Bug：视频播放器误报「视频损坏」（video-player）

> **状态：已修复（2026-11-24）** —— `MediaError` 按 code 分支映射（2→`VP_READ_FAILED`、3→`VP_PLAYBACK_FAILED`、4→`VP_CODEC_UNSUPPORTED`、1 不提示），`errors.ts` 新增 `playbackError` 并有 7 例单测；spec §5/§6 与 smoke 已同步。详见 `docs/spec/video-player.md`、`docs/smoke/video-player.md`。

- **现象**：视频播放器无法播放，提示「视频损坏」。
- **实际**：同一文件在其他播放器可正常播放。
- **排查方向**：编解码/容器格式支持范围；demuxer/解码器报错被误映射为「损坏」；错误文案与真实错误码区分（可能是不支持的编解码而非文件损坏）。
- **性质**：`fix/*` 修复，不涉决策变更；需补错误分支文案与 smoke 异常场景（不支持的编码）。

### 7.2 新功能：图片去水印（候选新工具，需 R8）

- **展示**：加载并展示图片。
- **交互**：用户手动圈出水印位置。
- **智能默认**：自动识别水印并默认预选识别结果（用户可调整）。
- **待细化**：识别方案（本地算法/OCR，可复用 `ocr-kit`）、填充方式（inpainting/模糊/纯色）、多区域支持、批量处理。
- **性质**：新工具候选 → 开工前须：§1 决策总表登记 + 字段级 spec + 依赖白名单评估（如引 inpainting 依赖须钉版 + audit + chunk 口径）+ R2 八类 smoke。
