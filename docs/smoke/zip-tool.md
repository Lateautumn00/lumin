## 2. R2 八类异常逐条

| 类别             | 场景与验证                                                                                                                                                                                                                 | 结果   |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 1. 中文/空格路径 | 单测/e2e 均用中文文件名（`素材.txt`/`输出.zip`/`往返.txt`）与中文条目；目录名保留中文（`甲/`、`子目录/`）；临时根目录保持 ASCII（本机 Node 对非 ASCII 目录名会硬崩，已知环境限制）                                              | 通过   |
| 2. 文件被占用     | 打包源以 `open(r)` 读取，失败统一 `ZP_SOURCE_INVALID`（detail 含 errno）；解压目标目录只用 `mkdir`/`write`，不可写归 `ZP_TARGET_INVALID`；单条失败整个任务报错，不写半成品（打包失败清理半成品 zip）                              | 通过   |
| 3. 加密文件       | 解压前解析中央目录，`flags bit0` 置位条目 → 整包拒绝 `ZP_ARCHIVE_INVALID`（detail 指出加密条目）；单测通过篡改中央目录 flags 覆盖                                                                                              | 通过   |
| 4. 超大文件       | 条目数上限 100,000（`ZP_TOO_MANY_ENTRIES`）、声明解压总大小上限 10 GiB（`ZP_ARCHIVE_TOO_LARGE`）、实际写入字节二次校验；打包读写 64KB 分块，不整文件入内存；单测注入 `maxEntries=1` / `maxBytes=1` 覆盖两条分支                       | 通过   |
| 5. 任务取消       | `pack`/`unpack` 走壳 `runTask` 三段式，UI 加载态「取消」→ `lumin:task:cancel` → worker terminate；取消事件归一 `CANCELLED` 显示「已取消」；打包被取消时删除未完成的产物 zip                                                                 | 通过   |
| 6. 并发溢出       | 工具自身无批处理；并发由壳任务队列上限协调，每次任务独立 worker 与独立 `Zip`/`Unzip` 实例，无共享状态；同一输出名并发由 `resolveConflictPath` 递增规避覆盖                                                                     | 通过   |
| 7. 磁盘满         | 打包写盘失败（ENOSPC 等）归 `ZP_TARGET_INVALID` 并删除半成品；解压写单条失败同上；e2e 用 ACL 不可写目录模拟目标不可写（`ZP_TARGET_INVALID` 单测覆盖）                                                                          | 通过   |
| 8. 断电恢复       | 打包先写目标 zip，完成前失败即 `unlink` 半成品；解压逐条原子落盘，无 `.tmp` 中间态，强杀后已解压文件仍完整可用；重启后可直接重跑同一任务（无脏状态）                                                                            | 通过   |

## 3. 安全防护口径

- **zip slip**：条目名先 `normalizeArchivePath` 归一；绝对路径、盘符前缀（`C:`）、UNC、`..` 段、控制字符一律判定非法 → 跳过并计入 `skipped`，不触磁盘。
- **符号链接**：fflate 不暴露 Unix mode，自解析中央目录 `externalAttrs` 高 16 位，`0xA000` 条目跳过计数。
- **ZIP64**：EOCD 标记 `0xffff`/`0xffffffff` 整包拒绝（明确不支持，避免解析歧义）。
- **压缩算法**：中央目录预检仅放行 store(0)/deflate(8)，其余拒绝。
- **不覆盖**：解压默认 `rename`（`{base} (n){ext}`），`skip` 直接跳过；打包产物同名走 `(n)` 递增。

## 6. 能力边界声明

- 仅支持 ZIP（`.zip`，store/deflate）；不支持 ZIP64、分卷、加密、RAR/7z。
- 解压不做内容级校验（CRC 由 fflate 校验失败时报 `ZP_ARCHIVE_INVALID`）；同名文件一律不覆盖。
- 打包不跟随符号链接（跳过），目录源保留空目录条目。

### 7.2 编码判定

| 场景                                   | 判定                                                          | 验证     |
| -------------------------------------- | ------------------------------------------------------------- | -------- |
| bit11 置位（UTF-8 名）                 | 直接 UTF-8 解码，不做 GBK 尝试                                 | 单测     |
| bit11 未置位 + UTF-8 可解（纯 ASCII）  | 保留 UTF-8 结果                                               | 单测     |
| bit11 未置位 + UTF-8 含 U+FFFD         | 原始字节回退 `TextDecoder('gbk')`，无替换符则采用              | 单测     |
| fflate latin1 折叠（U+0080–U+00FF）    | 还原字节后按 GBK 重解；成功 → 中文名                           | 单测     |
| GBK 也失败                             | 返回 `null` → 跳过计数 + 汇总提示，不落盘                      | 单测     |
| 中央目录与流式解压                     | 复用同一 `decodeZipEntryName`，符号链接键保持一致               | 静态审查 |
