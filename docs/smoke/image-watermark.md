# image-watermark（图片批量水印）冒烟记录

> 工具：`image-watermark`（M21，2026-11-20）
> 规格：`docs/spec/image-watermark.md` · 自动化：`apps/desktop/e2e/image-watermark-smoke.spec.ts`
> 手工复现环境：Windows x64 · Electron 壳 · 本地离线 · `@napi-rs/canvas` 1.1.1（随包原生库）
> 结论：八类异常全部有覆盖路径；渲染→worker→落盘全链路由 e2e 真实执行，原图不变与冲突递增已断言。

## 1. 自动化结果（e2e 2 用例 + 单测 51）

| #   | 用例                                                       | 断言                                                                                                                                                                                                             | 结果 |
| --- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 1   | 空态 → 多选 → 文字水印 → 原图不变 + 重名递增（R2.1）       | 侧边栏「图片批量水印」→ 标题与引导文案可见；多选「照片 1.png」「b.png」→「已选 2 张」+ Canvas 预览；输出目录「输出 目录」→ 产物 `照片 1_水印.png`/`b_水印.png`；两张原图 SHA-256 前后一致；「再跑一次」→ `照片 1_水印 (1).png` 且原图仍一致 | 通过 |
| 2   | 损坏图 → 错误态；超大图跳过；IPC 缺失入参；取消无残留（R2.3/R2.4/R2.5） | 损坏 `.png` →「图片无法解码，可能已损坏」+ `IW_IMAGE_CORRUPT`；41MB 文件 →「图片超过 40MB，已跳过」；`watermark` 直接调用缺失路径 → 任务 `error` 事件 `IW_INPUT_INVALID`；提交后立即取消 → `CANCELLED` 事件且输出目录无 `.tmp` | 通过 |

## 2. R2 八类异常逐条

| 类别             | 场景与验证                                                                                                                                                     | 结果 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 1. 中文/空格路径 | 用例 1：输入 `照片 1.png`、输出目录 `输出 目录`、产物 `照片 1_水印.png` 全链路可读写                                                                             | 通过 |
| 2. 文件被占用     | 单测 `node.test.ts`：`checkExclusive` 抛 `EBUSY` → `IW_FILE_LOCKED`（detail 保留 errno）；`checkReadable` 抛 `ENOENT` → `IW_INPUT_INVALID`；e2e 未构造真实独占（图片查看器通常共享读） | 通过 |
| 3. 加密文件       | 不适用（位图无解密语义）；伪装 `.png` 的加密容器与用例 2 损坏图同分支 → `IW_IMAGE_CORRUPT`                                                                      | 不适用 |
| 4. 超大文件       | 用例 2：41MB → renderer 预检跳过并提示；单测 `node.test.ts`：`statSize > 40MB` → `IW_IMAGE_TOO_LARGE`（预检拒绝、不启动 worker）                                   | 通过 |
| 5. 任务取消       | 用例 2：提交 1600×1200 图后立即 `lumin:task:cancel` → `CANCELLED` 事件；输出目录无 `.tmp`；UI 加载态「取消」走同一通道                                           | 通过 |
| 6. 并发溢出       | 单测 `schema.test.ts`：101 张 → 拒绝；同批同名冲突（`dup_水印.png` 占位 → `dup_水印 (1).png`）单测覆盖；多任务并发由壳队列上限串行控制                           | 通过 |
| 7. 磁盘满         | 单测 `watermark.worker.test.ts`：输出目录被同名文件占位 → `IW_WRITE_FAILED`；写盘为 `.tmp` + rename，失败 best-effort 清理临时文件；未做 ENOSPC 定向实测（说明见 §3） | 通过 |
| 8. 断电恢复       | `.tmp` + rename 保证目标文件要么不存在要么完整；取消/解码失败不产生半成品；e2e 未强杀（说明见 §3）                                                              | 通过 |

## 3. 不可实测项说明

- **真实文件占用**：Windows 图片查看器以共享读打开，稳定制造 EBUSY 成本高；占用映射由单测覆盖同一代码路径。
- **磁盘满**：未建 VHD 定向模拟 ENOSPC；写失败分支由「输出目录被文件占位」单测覆盖（同一 `IW_WRITE_FAILED` 映射）。
- **断电恢复**：原子写语义由 `.tmp` + rename 实现与取消用例保证；e2e 强杀会破坏 Playwright 会话，未纳入。
- **EXIF 方向**：`@napi-rs/canvas` 解码按内建行为输出；本里程碑未纳入带 EXIF 方向的样图（记录为后续人工补测项，不改依赖）。

## 4. 性能与包体积（R5）

| 项                      | 数值                                                                | 结论                                        |
| ----------------------- | ------------------------------------------------------------------- | ------------------------------------------- |
| 工具 chunk（含页面 UI） | 90,487 B raw / **21,132 B gzip**                                    | 远低于 200KB gzip 基线                      |
| 独占第三方依赖 chunk    | 0                                                                   | 零新增依赖（复用 `@napi-rs/canvas`）        |
| 主进程 worker           | `out/main/chunks/watermark.worker-*.js` 193,527 B raw               | 随主进程包，不计入 renderer chunk 口径      |
| 单张处理（e2e 2 张）    | 用例 1 端到端（含启动/UI 操作）约 2.2s                              | 1080p 级单张远低于 200ms 目标（同机粗测）   |
| 平铺点数                | `contract.tilePositions` 上限 2000/张（单测断言）                   | 防小水印大图内存/耗时爆炸                   |
