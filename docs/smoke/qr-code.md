> 规格：`docs/spec/qr-code.md` · 自动化：`apps/desktop/e2e/qr-code-smoke.spec.ts`

## 2. R2 八类异常逐条

| 类别             | 场景与验证                                                                                                                            | 结果             |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| 1. 中文/空格路径 | 用例 1：输出目录 `中文 目录`、文件名 `二维码 测试.png`；用例 2：识别内容含中文与空格                                                  | 通过             |
| 2. 文件被占用    | 不读取用户源文件（生成纯内存、识别走浏览器 `File` API），唯一写盘对占用目标自动 `(n)` 规避；占用导致的写失败与 7 同一分支（ACL deny） | 等价覆盖         |
| 3. 加密/损坏文件 | 用例 2：非图片字节 `.png` → `createImageBitmap` 失败 → `QR_IMAGE_UNREADABLE`；空白图 → `QR_DECODE_FAILED`                             | 通过             |
| 4. 超大文件      | 用例 5：21MB 占位图 → 体积预检 → `QR_IMAGE_TOO_LARGE`（20MB 上限）；PNG 保存数据 zod 上限 8MB 字符                                    | 通过             |
| 5. 任务取消      | 本工具无三段式长任务：保存为毫秒级同步写盘、识别在本机 renderer 完成；无取消按钮即无取消语义                                          | 不适用（有理由） |
| 6. 并发溢出      | 用例 4：5 次并发 `save` 各自冲突递增命名、产物全部有效；无共享可变队列                                                                 | 通过             |
| 7. 磁盘满        | 无法安全制造 ENOSPC；用例 5 用 ACL deny 写/删覆盖同一写盘失败分支 → `QR_OUTPUT_WRITE_FAILED`（可重试）                                | 等价覆盖         |
| 8. 断电恢复      | 写盘为「临时文件 + rename」原子提交；单测断言 rename 失败清理临时文件；强杀只会留下可忽略的 `.tmp-*`，目标文件要么不存在要么完整        | 等价覆盖         |

## 3. 单元测试与覆盖率

- `pnpm exec vitest run packages/tools/qr-code`：9 个测试文件 / **66 用例全绿**（M55 新增 `batch.test.ts` 10 例）。
- 覆盖：WiFi/vCard 转义、内容校验、文件名清洗、PNG base64 归一、原子写盘失败清理、三通道（config/set-output-dir/save）、样式钳制、QR 矩阵 → RGBA → jsQR 解码闭环、批量追加/上限截断/错误归类/汇总/TSV。
- 包覆盖率阈值 80%（lines/functions/statements/branches），随 `pnpm coverage` 校验：本包 lines 89.22 / functions 88.57 / branches 92.86（语句计入 lines），达标。

## 4. 性能与体量

- 工具 chunk（renderer）：**355,267 B raw / 85,163 B gzip**（含 `qrcode` + `jsqr` + 工具代码 + 批量编排），低于 R5 的 200KB gzip 上限。
- 识别：单张 400×400 图片在本机毫秒级完成；批量串行逐张解码（最多 50 张），进度可见且可取消；预览 300ms 防抖，无网络请求。
- 主进程零新增依赖（仅 `node:fs`），保存为原子写盘，无 worker。
