# batch-ocr（图片批量识别）冒烟记录

> 工具：`batch-ocr`（M28，2026-11-20）
> 规格：`docs/spec/batch-ocr.md` · 自动化：`apps/desktop/e2e/batch-ocr-smoke.spec.ts`
> 手工复现环境：Windows x64 · Electron 45.3.1 · 本地离线 · `binaries/ocr` 模型齐全（det/rec/字典）
> 结论：八类异常全部有覆盖路径；真实多图推理由 e2e 直连 PP-OCR 验证，导出走 IPC 契约（原生目录选择框不可自动化）。

## 2. R2 八类异常逐条

| 类别             | 场景与验证                                                                                                                                                              | 结果 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 1. 中文/空格路径 | 用例 2：输入 `sample 1.png`、输出目录 `中文 目录`、产物 `sample 1-OCR.txt` 全链路可读写                                                                                  | 通过 |
| 2. 文件被占用     | 单测 `node.test.ts`：`checkExclusive` 抛 `EBUSY` → 该项 `BO_FILE_LOCKED`（`detail` 保留 errno），其余图片继续识别；e2e 未构造真实占用（图片通常以共享读打开）             | 通过 |
| 3. 加密文件       | 不适用（图片无解密语义）；加密容器伪装 `.png` 走渲染失败分支 → 单项 `BO_OCR_FAILED`/`BO_INPUT_INVALID`，不影响整批                                                      | 不适用（已说明） |
| 4. 超大文件       | 用例 1：21MB PNG → 单项 `BO_IMAGE_TOO_LARGE`（「图片超过 20MB…」），预检即拒绝、不启动 worker                                                                            | 通过 |
| 5. 任务取消       | 单测 `node.test.ts`：`signal` 原样传给 `runTask`（壳终止 worker → `CANCELLED`）；UI 识别中显示进度与「取消」；多图识别耗时可观测，e2e 未断言取消时点                      | 通过 |
| 6. 并发溢出       | 用例 3：5 个导出并发文件名互不冲突；识别任务由壳队列并发上限控制，超限排队；单批 50 张上限由 schema 拦截                                                                | 通过 |
| 7. 磁盘满         | 导出走 `writeAtomic`（临时文件 + rename）；写失败 → `OUTPUT_WRITE_FAILED`（单测覆盖 ENOSPC 映射与失败透传），不残留半成品；未做 ENOSPC 定向实测（说明见 §3）             | 通过 |
| 8. 断电恢复       | `writeAtomic` 保证目标文件要么旧内容要么完整新内容；识别无中间产物；e2e 未强杀（说明见 §3）                                                                              | 通过 |

## 3. 不可实测项说明

- **真实文件占用**：Windows 下图片查看器以共享读打开，难以稳定制造 EBUSY；占用映射由单测覆盖同一代码路径。
- **磁盘满**：未建 VHD 定向模拟 ENOSPC；导出写失败分支由单测（注入 `writeAtomic` 抛 `ENOSPC`）覆盖。
- **断电恢复**：原子写语义由 `node-kit.writeAtomic` 单测与实现保证；e2e 强杀会破坏 Playwright 会话，未纳入。
- **取消时点**：批量识别耗时取决于张数；取消链路复用壳通用 `lumin:task:cancel`（已在 shell 冒烟覆盖），本工具单测验证信号透传。

## 5. 设置记忆

- 键：`tools.batch-ocr.outputDir`（导出目录）；缺省 `userData/batch-ocr`。
- e2e 未覆盖记忆回填（导出走 IPC 契约、绕过原生目录选择框）；目录记忆与缺省回落由 `node.test.ts` `config` 用例覆盖。
