# 文件哈希校验（file-hasher）冒烟记录

> 版本：v0.1.0 · 日期：2026-11-19 · 环境：Windows 11 x64 / Node 22 / Electron（本地构建）
> 依据：AGENTS §7.3（R2 八类全覆盖）+ §8（R5 chunk）+ §5.3（三态）。
> 自动化用例：`apps/desktop/e2e/file-hasher-smoke.spec.ts`（7/7 通过）；单测：`pnpm vitest run packages/tools/file-hasher`（36/36）。

## 1. R2 八类异常

| # | 场景         | 操作与样本                                                             | 实测结果                                                                 | 结论 |
| - | ------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------ | ---- |
| 1 | 中文/空格路径 | `%TEMP%\lumin-fh-e2e-cn\文件 一.txt`、`文件 二.txt`（内容 `abc`）      | 三算法值与 RFC 向量一致；结果顺序 = 入参顺序；`totalBytes=6`             | 通过 |
| 2 | 文件被占用   | PowerShell `[IO.File]::Open(path,'Open','Read','None')` 独占持有后读取   | 读取失败 `EBUSY` → 该行 `FH_HASH_FAILED`（详细信息 `EBUSY`），整批继续    | 通过 |
| 3 | 加密文件     | `cipher /e` EFS 加密后计算 SHA-256                                     | 正常读出明文摘要（读取透明解密），无报错                                 | 通过 |
| 4 | 超大文件     | ① 20 GB + 1 字节稀疏文件（`fs.truncate`）② 256 MB 实体文件             | ① 该行 `FH_FILE_INVALID`「文件超过 20 GB 上限」，`totalBytes=0`；② 正常完成（256 MB 单任务 < 3s） | 通过 |
| 5 | 任务取消     | 256 MB + 2 个小文件提交后立即 `lumin:task:cancel`                      | 终态 `CANCELLED`（极快完成时 `done`），无残留任务、页面可再次提交        | 通过 |
| 6 | 并发溢出     | 同时提交 3 个 `file-hasher:hash` 任务                                  | 队列按默认并发调度，3 个任务全部 `done`，各自 `totalBytes=1 MB` 无串扰   | 通过 |
| 7 | 磁盘满       | 本工具**只读不写**，无落盘路径；以 ACL 拒绝读取（`icacls /deny 用户:(R)`）作等价失败代理 | 读取 `EPERM` → `FH_HASH_FAILED`（`EPERM`），不产生任何写入              | 通过 |
| 8 | 断电恢复     | 256 MB 任务执行中 `taskkill /F /T` 强杀主进程 → 重新启动               | 重启后主界面正常、同一文件重算成功（`sha256` 64 位十六进制）             | 通过 |

> 注：第 2 类中 Windows 下 Node 默认以共享模式打开，故用 `FileShare.None` 独占句柄复现真实占用；第 7 类为只读工具，磁盘满不适用，按 R2 以「读取失败代理」覆盖错误分支。

## 2. 三态验收

| 状态   | 断言                                                                                  | 结果 |
| ------ | ------------------------------------------------------------------------------------- | ---- |
| 空态   | 未添加文件显示「添加文件后点击『开始校验』，即可获得哈希值」+ 拖拽区                  | 通过 |
| 加载态 | 进度阶段（准备/计算）+ 已处理/总字节 + 当前文件名 + [取消] 可点击                     | 通过 |
| 报错态 | 结构化错误码 → 中文文案 + [重试]（文件类）+ [详情]折叠显示 errno                       | 通过 |

## 3. 功能与交互

| 项                 | 实测                                                                 | 结果 |
| ------------------ | -------------------------------------------------------------------- | ---- |
| 三算法一致性       | `abc` → MD5 `900150983cd24fb0d6963f7d28e17f72` / SHA-1 `a9993e364706816aba3e25717850c26c9cd0d89d` / SHA-256 `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad` | 通过 |
| 期望哈希比对       | `MD5:<大写>` 粘贴 → 「按 MD5 比对，命中 1 个文件」+ 行高亮 + 「匹配」 | 通过 |
| 非法期望哈希       | 长度/字符非法 → 红字「格式非法」                                      | 通过 |
| 复制单行 / 复制全部 | TSV 文本（含表头，列=已选算法），失败行含错误码                       | 通过 |
| 失败项重试         | 仅重算失败路径（不重算成功项）                                        | 通过 |
| 算法记忆           | 重进页面沿用上次勾选（`set-config` 持久化，非法存量回落 SHA-256）     | 通过 |

## 4. chunk 实测（R5）

| 产物                                       | raw      | gzip     | 口径说明                                            |
| ------------------------------------------ | -------- | -------- | --------------------------------------------------- |
| `renderer/assets/file-hasher-BkeUnipT.js`  | 29,793 B | 8,854 B  | 工具 chunk（含 schema/contract/视图），基线 200KB   |
| `main/chunks/hash.worker-bce15ce6.js`      | 182,722 B| 42,442 B | 主进程 worker（R5 不计 renderer 口径），单列备案     |

结论：工具 chunk **8.6KB gzip**，远低于 200KB 基线；无新增第三方依赖（`node:crypto` + `node:fs`）。

## 5. 已知限制

- 拖入文件夹不展开（提示「请拖入文件」），不支持递归目录哈希（spec §1）。
- 复制依赖剪贴板权限，失败时降级 `document.execCommand('copy')` 并提示手动复制。
- 单次 200 文件 / 单文件 20 GB / 任务 30 分钟超时（spec §4）。
